# 検証した範囲

## このリポジトリで確かめたこと

2026-11-03 に、Windows 11・Node.js 24.13.1・npm 11.8.0 で次を実行しました。

| コマンド | 結果 |
|---|---|
| `npm install` | 成功（`node_modules` を消した状態から） |
| `npm test` | 16 ファイル・156 件すべて成功 |
| `npm run typecheck` | エラー 0（`src` と `examples` が対象） |
| `npm run example` | 成功。`list.json` と `body.json` を出力し、どちらも ID 1〜8 の 8 枚 |

同日、Linux・Node.js 24.22.2・npm 10.9.0 でも、ロックファイルからの `npm ci`、156 件のテスト、型検査、サンプル実行を再確認しました。

テストは vitest の node 環境で動き、SDK の bridge にもシミュレーターにも接続しません。確かめているのは、部品が返す container の値（座標・寸法・色・内容・ID）と、タイマーや入力の規則の振る舞いです。タイマーは vitest の偽のタイマーで進めています。

## 確かめていないこと

- シミュレーターや実機での表示。`npm run example` の JSON を描画した結果は見ていません
- 実機のタッチパッドや R1 での操作感、350ms・200ms・400ms などの時間が適切かどうか
- 文字幅の見積もり（`@evenrealities/pretext`）と実機の描画幅の差。安全余白 12px で足りるかどうか
- 全角・半角空白による右寄せ（`fillGap()`）の実機での位置
- OS メニューの上限 10 個にシステム側の項目が含まれるかどうか
- 埋め草（ID 1〜8 のうち使わない面）が header・right より後に重なっても実機で見えないかどうか
- 標準値の使いやすさ。複数の人に使ってもらって比べたことはありません

## コメントに残っている観測について

ソースのコメントには、元の開発環境での観測が残っています。例えば、pretext は半角空白の幅を 5 と返すがシミュレーターでは 16/3px 送る、シミュレーター 0.9.1 は OS メニューを 10 項目受け付けて 5 項目ずつ表示した、pretext の見積もりは実機より狭い、といった記述です。これらは元のアプリを作ったときの記録で、このリポジトリでは測り直していません。

## 切り出しで外したもの

元の共通部品には、`events` の読み方を移行前のアプリの実装と全組み合わせで突き合わせるテストがありました。比較に使うフィクスチャが元のアプリに依存するため、このリポジトリには含めていません。`events` の分類の表、読み順で結果が変わる例、スワイプの間引きのテストは残しています。
