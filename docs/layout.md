# レイアウト

画面は 576×288px です。座標と寸法の値はすべて `src/ui/tokens.ts` の `GLASS` にあり、この文書の値はそこから写しました。値が食い違ったときは `tokens.ts` の値を優先してください。

## 全体の割り付け

```
y 0   ┌ 上段 (h 28) ─ header (x 12〜) ………… right (右端 x 564) ┐
y 32  ├ 本文枠 または 一覧の枠 (x 8, w 560)                        │
      │                                                            │
y 284 └────────────────────────────────────────────────────────────┘
y 288
```

| 部分 | 値 |
|---|---|
| 画面 | 576×288 |
| 上段 | 高さ 28。header は x 12・y 0・h 28・textColor 3 |
| right（位置・時計） | 右端 x 564（header の x 12 と左右対称）、y 0・h 28・textColor 3 |
| header と right の間 | 8px（`TOP_GAP`） |
| 本文枠 | x 8・y 32・w 560・h 252、borderWidth 2・borderColor 15・borderRadius 12・padding 4。内寸 548×240 で 8 行 |
| 一覧の枠 | x 8・w 560、borderWidth 2・borderRadius 12・padding 2。先頭 y 32、下端の上限 284、間隔 3 |
| 画像 | 400×200 を (88, 58) に置く値だけを持つ。画像の部品はこの部品集に含まない |

## container ID

text container は全画面で ID 1〜8 の 8 枚にそろえます。画面を作り直したときに枚数が減ると、消えた面に前の画面の文字が残るためです。`padToFixedSet()` が足りない ID を見えない埋め草で埋めます。

| ID | 役割 |
|---|---|
| 1 | overlay。全面（0, 0, 576, 288）・枠 0・content 空。`isEventCapture: 1` を持つのはこの 1 枚だけ |
| 2 | header |
| 3〜 | 表示面（本文枠・一覧の枠・確認の枠）。`idBase` で開始番号を変えられる |
| 8 | layout が `'two'` のときだけ right。`'one'` では表示面に使える |

入力を受ける container の文字はスワイプのたびに上下に弾むため、入力受けは中身が空の overlay に限っています。header・right・表示面の `isEventCapture` は 0 です。

埋め草は x 12・y 0・w 552・h 28、borderWidth 0、content は半角空白 1 字（空文字にすると contentLength が 0 になるため）です。

## 上段の 2 つの形

表示面をいくつ使う画面かで、上段の形を決めます。

| layout | container | 表示面の上限 | 使う画面 |
|---|---|---|---|
| `'one'` | overlay + header | 6 | 表示面を 6 枚使いうる画面（項目が 6 件以上の一覧、選択肢 5 個の確認） |
| `'two'` | overlay + header + right | 5 | それ以外（本文枠の画面など） |

`topLayout(maxFaces)` は、maxFaces が 6 以上なら `'one'`、5 以下なら `'two'` を返します。maxFaces は、今のデータでその画面が使いうる表示面の最大枚数です。一覧なら項目数、確認なら 1 + 選択肢の数で数えます。カーソル位置や、空・読み込み中・エラーといった状態で形を変えることはしません。

`'two'` の right の内容は次の順に並びます。

```
[未接続　][━━━━━━━─── ][07/10　]14:32
```

right の幅は「内容の数字をすべて `4` に置き換えて測った幅 + 4px」です。時刻や位置の数字だけが変わるときは幅が変わらないので、container を作り直さずに文字の更新で済みます。未接続の表示、総数の桁数、進捗バーの有無が変わると幅が変わります。この判定には `topBar()` が返す `shapeKey` を使います。

`'one'` では header 1 枚に「題名 + 空白 + right と同じ内容」を入れます。SDK に右寄せが無いため、全角空白（20px）と半角空白（16/3px）の組み合わせで右へ送ります（`fillGap()`）。この送り幅はシミュレーターの描画から測った値で、題名によって位置・時計の x が最大 3px ずれることが元のコメントに記録されています。

## 一覧

1 項目を 1 つの枠にします。

| | 枠 | 文字 | 行数 |
|---|---|---|---|
| 選択中 | borderColor 15 | textColor 4 | 最大 8 行（9 行以上なら上から 8 行を残す） |
| ほか | borderColor 5 | textColor 2 | 1 行（幅を超えたら `…` で切る） |

枠の高さは `ceil(行数 × 27 + 8)` です。1 行で 35、2 行で 62、3 行で 89、8 行で 224 になります。1 ページに出す枠は最大 6 枚で、下端 284 を超えない範囲で詰めます。

ページは 1 行ずつ流さず、まとめて切り替えます。

- 選択中の項目が今のページに収まるなら、ページはそのまま
- 下へ動いて収まらなくなったら、選択中の項目を先頭にしたページへ切り替える
- 上へ動いてページの外に出たら、選択中の項目を末尾にして後ろから詰めたページへ切り替える

選択中の項目の行数が項目ごとに違っても、この規則で決まります。`layoutList()` が返す `pageStart` をアプリが保持し、次の呼び出しに渡します。

## 確認

本文枠を上に縮めて問いを出し、その下に選択肢を一覧と同じ枠で縦に積みます。選択肢は 1〜5 個で、問いの枠と合わせて表示面は最大 6 枚です。

| 選択肢の数 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 問いに使える行数 | 7 | 6 | 4 | 3 | 2 |

問いの枠の高さは「252 − 選択肢の枠の高さの合計 − 間隔」です。問いが入りきらないときは末尾を `…` にします。

## 本文の下のヒント

初めての画面では本文枠の高さを 220 に縮め、x 12・y 256・w 552・h 28・textColor 2 の 1 行を置きます。

## 中央に置く 1 行

読み込み中の表示などは、本文枠（中身は空）と、その中央に置いた 1 行の 2 枚で組みます。SDK に text-align が無いので、先頭の改行や空白でずらすことはせず、文字の実測幅 + 4px の container を作って x・y を計算します（`centeredLabel()`）。

## 文字幅と安全余白

G2 のフォントはプロポーショナルで、カーニングもあります。表示に載せる文字列の幅は `@evenrealities/pretext` の `getTextWidth` で測り、文字数では切りません。

折り返し・切り詰めの幅は「内寸 − 12px」を使います。本文枠・一覧の枠とも 548 − 12 = 536px です。元のコメントによると、pretext の見積もりは実機より狭く、内寸ちょうどで折ると実機で折り返し直されることがありました。`centeredLabel()` は幅を実測から決めるので、この余白を使いません。

text container の content は 999 byte が上限です。`clampToBytes()` で収めます。

## 区切りと記号

| 用途 | 値 |
|---|---|
| header・meta の項目間 | 全角空白 `　` |
| 位置と時計の間 | 全角空白 `　`（例 `03/24　14:32`） |
| 位置 | 総数の桁までゼロ埋め（`position(3, 24)` → `03/24`） |
| 進捗バー | `━`（済）と `─`（残）の 10 マス。1 ページでも読んでいれば 1 マス埋める |
| 状態記号 | `●` 実行中 / `○` 待機 / `◆` 要対応 / `─` 終了 / `★` ピン留め / `▲` `▼` 続きあり |
| 切り詰め | `…`（1 文字） |
